## 一、一句话定位

**把散落在各平台的灵感素材（截图、文本）统一收进来，由 AI 自动总结分类，需要设计灵感时能按主题快速找回。**

---

## 二、目标用户与策略

### 已确认策略：自用先行 + 预留扩展

| 阶段 | 用户范围 | 目的 |
|---|---|---|
| **第一版** | **只有你自己**（第一个正式用户） | 按真实使用习惯打磨核心功能，反馈闭环最短 |
| 后续 | 开放给有同类需求的设计师 / 学生 | 需要时再实现登录与多用户 |

> **这个策略很好，但有一个必须防住的坑**：只有自己一个用户时，很容易**把个人习惯误当成通用需求**。比如你习惯用某几个标签，就默认所有人都这么分。
>
> **防法**：第一版的所有数据结构里，凡是「与用户绑定」的字段（归属、偏好、分类体系）**都预留 user_id**，但先不实现登录。这样后续开放时，改的是「谁来访问」，不是「数据长什么样」。

### 关于「登录」的取舍（需要你确认）

| 方案 | 工期影响 | 说明 |
|---|---|---|
| **A. 第一版不做登录，数据存在浏览器本地** | 最省 | 换设备数据不同步，但自己用够 |
| **B. 第一版不做登录，但数据结构预留 user_id、存储层做抽象**（推荐） | 几乎无额外成本 | 后续接云端不用重写业务逻辑 |
| C. 第一版就做登录 + 云端存储 | +2~3 天，且需要后端 | 好处是手机电脑都能访问 |

**我的建议：走 B。** 「预留接口」和「实现功能」是两件事——你要的是前者，成本极低，收益很大。

> 如果你确实需要**手机截图、电脑整理**的跨设备体验，那就要走 C，但工期要重新排。

## 三、用户痛点

### 现状

你在各个平台遇到有价值的内容——小红书的案例推文、公众号的设计文章、网页上的参考图、随手截的图——它们散落在各自的 App 里。

### 现有替代方案为什么不够用

| 现在怎么凑合 | 问题 |
|---|---|
| 用平台自带的收藏（小红书收藏夹、微信收藏） | **锁死在单一平台**；只能按时间堆叠；**收藏即遗忘** |
| 截图存相册 | 相册里混着生活照，无从检索；没有上下文（这是哪来的、为什么存） |
| 复制粘贴到备忘录 / Word | 手工整理负担重；图片和文字混在一起；**整理成本高到不会去做** |
| 存到 iCloud 网盘 | 只是「存放」，没有分类、没有摘要、没有检索维度 |

### 痛点的本质

**不是「存不下来」，是「存下来之后找不回来」。** 现有工具都在解决「存」，没有解决「用」。

## 四、使用场景

| 场景 | 触发时机 | 期望行为 |
|---|---|---|
| **随手收集** | 刷小红书/公众号时看到好案例 | 截图或复制文本 → 丢进去 → 不用管了（AI 自动处理） |
| **设计前找参考** | 做方案前需要同类案例 | 输入关键词（如「工业遗址」「屋顶花园」）→ 找到之前存的相关素材 |
| **回顾与串联** | 想看看自己最近关注什么 | 按分类浏览素材库，发现规律（如"我最近一直在存适老化设计"） |
| **方案汇报引用** | 需要一个参考案例支撑方案 | 从库里直接调出素材，附上来源 |

## 五、目标与成功标准

### 产品目标（第一版）

验证一个核心假设：**AI 自动总结分类的结果足够准，准到我愿意持续录入而不用手工整理。**

### 成功标准（可量化）

| 指标 | 目标值 | 衡量方式 |
|---|---|---|
| 录入耗时 | 单条素材 **≤ 30 秒**（含上传与等待 AI 处理） | 自己掐表 |
| AI 标签可用率 | 自动生成的标签中，**≥ 70% 不需要我手动修改** | 统计前 50 条素材的修改次数 |
| 找回效率 | 积累 **≥ 50 条**素材后，能在 **10 秒内**找到想找的那条 | 实际测试 10 次取平均 |
| 持续使用意愿 | 连续 **2 周**保持录入，未放弃 | 看自己的实际使用记录 |

> **第 4 条最重要。** 这类工具最常见的失败方式不是功能不够，而是**录了两周就没人再录入**。如果做不到持续使用，前三条指标再好看也没有意义。

## 六、现有方案对比（初步）

| 类型 | 代表 | 优势 | 缺口 |
|---|---|---|---|
| 平台内置收藏 | 小红书收藏夹、微信收藏 | 采集最方便 | 单一平台、无分类、无检索维度 |
| 稍后读 / 剪藏工具 | Cubox、Pocket 类 | 网页与文章采集强 | 以长文为主，**对图片/截图场景弱**，分类靠手工 |
| 通用笔记工具 | Notion、飞书、Obsidian | 灵活、可自定义 | **完全没有自动分类**，整理成本高 |
| 设计素材站 | 花瓣、Pinterest | 图片采集与视觉浏览好 | 分类依赖用户手动建画板；**不处理"为什么存"** |

**差异化定位**：现有工具都在解决「**收集**」，本产品的差异点是「**AI 自动理解与分类**」+「**面向设计复用的检索**」。

> ⚠️ 本节为基于常识的初步分类，**尚未实际调研验证**。如需在面试中引用竞品数据，必须先核实。

## 七、MVP 范围

### ✅ 做（5 项）

| # | 功能 | 说明 | 优先级 |
|---|---|---|---|
| 1 | **素材录入** | 支持两种方式：① 粘贴文本；② 上传 / 粘贴截图 | P0 |
| 2 | **AI 自动处理** | 生成一句话摘要 + 3–5 个标签 + 自动归入分类 | P0 |
| 3 | **素材库浏览** | 卡片列表：缩略图 + 摘要 + 标签 + 来源 | P0 |
| 4 | **检索与筛选** | 按关键词搜索；按标签 / 分类筛选 | P0 |
| 5 | **素材详情与编辑** | 查看原图/原文、手动改标签、删除 | P1 |

### ❌ 不做（6 项，每条都有理由）

| 不做 | 理由 |
|---|---|
| **跨平台自动抓取** | 技术上有限制，合规上更敏感。**先做手动上传，把 AI 分类与检索做扎实** |
| **账号体系与多用户** | 第一版只有一个用户；但数据结构预留 user_id（见第二章） |
| 浏览器插件 | 开发成本高，且采集方式的优化应该等核心价值验证后再做 |
| 团队协作 / 分享 | 解决的是留存问题，不是验证问题 |
| 移动端 App | 网页做响应式即可覆盖手机使用 |
| 自动生成设计建议 / 方案 | 这是另一个产品的范畴，会把范围撑爆 |

> **「不做」每一条都能讲出理由**，这是面试高频追问。建议现在就记住这六条的理由。

## 八、核心流程（用户路径）

```
【录入】
打开工具 → 粘贴文本 或 上传/粘贴截图 → 点击「收进灵感库」
        → AI 处理中（预计 3–10 秒）
        → 返回结果：摘要 + 标签 + 分类 + 可手动修正
        → 完成

【找回】
打开灵感库 → 三种入口：① 关键词搜索 ② 标签筛选 ③ 分类浏览
          → 看到卡片列表 → 点开详情
          → 查看原图/原文 + 来源链接 + 我当初的备注
```

**关键设计原则**：录入路径必须**短到可以随手完成**。如果录入要超过 30 秒，这个工具就会死掉——因为灵感出现的那一刻你正在刷手机，不可能停下来做复杂操作。

## 九、数据模型（第一版）

### 素材对象（Item）

| 字段 | 类型 | 说明 | 必填 |
|---|---|---|---|
| `id` | 唯一标识 | | 是 |
| `user_id` | 用户标识 | **第一版固定值，但字段必须存在**（预留扩展） | 是 |
| `source_type` | 枚举 | 文本 / 图片 | 是 |
| `raw_text` | 文本 | 粘贴的原始文本（图片上传时为空） | 条件 |
| `raw_image` | 图片 | 截图或上传的图片 | 条件 |
| `source_platform` | 枚举 | 小红书 / 公众号 / 网页 / 其他，**用户手选，不做自动识别** | 否 |
| `source_url` | 链接 | 原文链接（如果粘贴时带了） | 否 |
| `ai_summary` | 文本 | AI 生成的一句话摘要 | 是（自动） |
| `ai_tags` | 标签数组 | AI 生成的 3–5 个标签 | 是（自动） |
| `category` | 分类 | AI 归入的顶层分类 | 是（自动） |
| `my_note` | 文本 | 我自己的备注（为什么存它） | 否 |
| `created_at` | 时间 | 录入时间 | 是 |
| `status` | 枚举 | 处理中 / 已完成 / 处理失败 | 是 |

### 分类体系（**需要你确认**）

三种方案：

| 方案 | 做法 | 优点 | 缺点 |
|---|---|---|---|
| A. 固定分类 | 预设 6–8 个顶层分类 | 稳定、检索快 | 不够灵活，新类型无处安放 |
| B. 纯 AI 自由标签 | 不设分类，全靠标签 | 最灵活 | 标签会发散（"工业遗址"和"旧厂改造"变成两个），越积越乱 |
| **C. 混合（推荐）** | 预设顶层分类 + AI 自由生成标签 | 兼顾可控与灵活 | 需要先想清楚顶层分类 |

**如果走 C，顶层分类建议**（需要你按自己的实际需求调整）：

- 空间与场所（城市、建筑、景观案例）
- 材质与构造
- 视觉与排版（配色、字体、版式）
- 图文表达（文案、叙事、汇报方式）
- 工作方法（流程、工具、经验帖）
- 待定 / 未分类

> ⚠️ **这是本产品最关键的设计决策**。同类工具失败的主因就是分类体系设计不当——**素材越积越乱，最后放弃使用**。请你认真想一下：**你平时找灵感时，脑子里最先冒出来的是哪个维度的词？**（是"工业遗址"这种主题词，还是"屋顶花园"这种要素词，还是"想做但还没做的方向"？）

## 十、关键取舍与设计决策

| 决策点 | 选择 | 理由 |
|---|---|---|
| 采集方式 | 手动上传优先，自动抓取后置 | 自动抓取有技术与合规风险，会卡住整个项目 |
| 用户范围 | 自用先行，预留扩展 | 反馈闭环最短；但数据结构必须预留 user_id |
| 分类策略 | 预定义顶层分类 + AI 自由标签 | 纯自由标签会发散；纯固定分类不够用 |
| 来源平台 | 用户手选，不做自动识别 | 自动识别平台需要解析 URL，成本高收益低 |
| 备注字段 | 保留 `my_note` | **「为什么存它」比「它是什么」更有价值**——这正是普通收藏夹缺失的 |

## 十一、风险清单

| # | 风险 | 影响 | 应对 |
|---|---|---|---|
| 1 | **录入摩擦太大，用两周就放弃** | 致命 | 录入路径控制在 30 秒内；先不要登录、不要必填项 |

| 3 | AI 图片理解质量不达预期 | 高 | 前 20 条素材人工核对 AI 标签的准确率；不行就退回"图片 + 手动标签" |
| 4 | 跨平台内容处理受限 | 中 | 已排除出第一版 |
| 5 | 做成"另一个收藏夹" | 中 | 检验标准：**能不能在 10 秒内找回 3 个月前存的东西** |
| 6 | 开发时间超预期 | 中 | 严格守住「不做清单」的 6 条 |
