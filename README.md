# Elangit · 个人灵感库

把散落在各个平台的灵感素材（截图、文本）收进来，由 AI 自动摘要分类，需要时按主题快速找回。

**它同时是两件事**：用户（风景园林硕士，转产品经理）日常真的在用的工具，以及他求职作品集里唯一能直接证明产品能力的原创项目。

## 快速开始

```bash
cd app
python3 _serve.py          # http://127.0.0.1:8791
```

右上角「解锁编辑」输口令进入所有者模式（可录入、可编辑、可分享）。不输口令就是访客视角。

## 公开仓库与本地磁盘的差异（重要）

本目录在同一台机器上承担两个角色：**Codex 的工作区**（要真值才能跑）和**公开仓库的上游**（不能带真值）。
所以 `tools/push-to-github.py` 是「边传边改」，上传的那一份和磁盘上的这一份**有意不一样**：

| 内容 | 本地磁盘 | 公开仓库 |
|---|---|---|
| `app/config.js` · `publishableKey` | 真值 | 占位符 `wbpk_<你的 publishableKey>` |
| `app/config.js` · `ownerPasscodeHash` | 真值（SHA-256） | `''`（空值 → 所有者模式永不通过） |
| `docs/09-简历…md` · 手机号 / 邮箱 | 真值 | `【你的手机号】` / `【你的邮箱】` |
| `data/` 下的数据（`dump.sql`、`items.json`、`images/`、`originals/`） | 有 | **不上传** |
| `docs/07-个人基础资料（私密）.md` | 有 | **不上传** |
| 其余（文档、源码、`schema.sql`、`data/tools/`、截图） | 有 | 原样上传 |

**要跑应用，用磁盘上这份**（`cd app && python3 _serve.py`）——从 GitHub clone 下来的那份没有真凭据，跑不起来，这是预期的。

**不要在这个目录里直接 `git push`**：那会把真值发出去。发布统一走 `tools/push-to-github.py`。

## 应用构成

| 页面 | 作用 |
|---|---|
| `app/index.html` | 素材库（首页）：侧栏抽屉/标签 + 卡片栅格 + 搜索 + 筛选 + 收藏夹分享 |
| `app/add.html` | 录入：粘贴/拖拽/点选 → 本地出图入库 → AI 异步补齐 → 就地改 |
| `app/item.html` | 素材详情：原图/原文/来源/摘要/抽屉/标签/备注/换封面/改动对照/删除 |
| `app/share.html` | 访客只读页（`/s/令牌`、`/i/令牌`、`?t=令牌`、`#令牌`） |
| `app/stats.html` | 数据页（仅所有者）：验收进度 + 6 个指标面板 |

**技术上的三个关键选择**（详细理由见 `docs/06-技术方案.md`）：

1. **不做账号体系**，所有者保护退化为纯前端口令——它拦的是误操作与路人，不是攻击者。
2. **图片以 base64 存进数据库**，不用对象存储——因为平台存储只对已登录用户开放，而分享页要给未登录的访客看。
3. **AI 异步补齐**，不阻塞录入——首页本地 ≤1 秒出图入库，AI 结果随后补上，60 秒超时降级为手填。
