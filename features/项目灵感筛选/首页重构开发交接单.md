## 2. 用户确认的 UI／交互基线（重点）

### 2.1 视觉

- **遵从现有 Elangit**：白底、浅灰细边框、系统中文字体、克制阴影、紧凑但不拥挤；不要改成米色画册、渐变背景或强装饰风。
- 中央卡是唯一明确焦点；右下角爱心要比正文视觉更清楚，但不压过卡片标题。
- 顶栏左为“新建项目”，右为“添加素材”；底部中间为“进入素材库”。

### 2.2 牌堆几何

- 卡片**只沿水平方向**向左右叠放，绝不改成上下堆叠。
- 桌面端：中央主卡两侧都要有**至少四层**可见预览卡；越往外越小、越淡，仍能看出是连续牌堆。
- 手机端：外围预览卡要明显缩小并减弱，避免挤压主卡；保留每侧至少三层的层次感，但最外层可隐藏。主卡始终优先。
- 直接复用 `app/projects/projects.js` 与 `app/projects/projects.css` 已实测过的牌堆几何、翻面、拖拽、鼠标滚轮／触控板模型；不要另写第二套不一致的交互逻辑。

### 2.3 操作语义（已在项目翻阅页验证）

- 左右拖动翻页；键盘左右键等价；触控板横向滚动为 1:1 跟手、逐格连续翻页、不封顶、到边界停住。
- **点侧卡 = 跳到那一张成为中央卡，不翻面。**
- **点中央卡 = 翻面／翻回正面**；背面进入素材详情。
- 进入下一张前必须先复位当前翻面状态；拖拽、按钮、侧卡点击、滚轮都走同一个翻页入口。
- 爱心固定卡片右下区域；已收藏红色，再点取消收藏，须有明显的缩放／颜色变化和“已取消收藏”反馈。

## 6. 绝对不要再踩的坑

1. **不要覆盖或删掉原素材库。** 必须先迁到 `library.html`，再把根首页换成翻阅；“有新首页”不等于旧能力可以消失。
2. **不要把 Demo 当正式代码复制粘贴。** `_demo_home.html` 的数据与交互是静态示意，正式实现必须复用 store 数据层和项目牌堆代码。
3. **不要为首页另写牌堆逻辑。** 已验证的连续滚动、翻面复位、侧卡点击语义都在 `app/projects/projects.js`；两套逻辑会马上产生手感与修复漂移。
4. **不要用 `pointer-events:none` 阻止侧卡翻面。** 子面上的 `pointer-events:auto` 会穿透这个“防线”。正确做法是事件中先判中央／侧卡：侧卡 `goTo()`，只有中央卡翻面（见修改记录 #024）。
5. **不要把滚轮重新做成“一次甩动”。** 当前模型是 1:1、逐格、余量跨事件累积、无上限，见 #025。
6. **不要读大图。** 首页翻阅队列走轻量索引和缩略图；`item_images.data_base64` 会把列表加载拖到不可用。
7. **不要页面直连数据库或绕过 `guard()`。** 项目、新建、收藏、取消收藏全部经 `store.js`；同一素材可属于多个项目。
8. **不要把空项目名直接写进列。** PostgreSQL 的 default 仅在省略列时生效；`null`／空串／纯空白必须归一为“未命名项目”。
9. **不要只凭 UI 判断测试清理完成。** 真实数据库回读是固定收尾步骤。
10. **不要发布、不要 Git 操作、不要动既有分享令牌规则。** 这些都需要单独用户确认；本交接只授权本地实现与验证。
