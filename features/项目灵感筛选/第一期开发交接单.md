## 0. 范围与不可动边界

本期只交付「建立项目 → 按项目标签翻阅既有素材 → 收藏为项目素材 → 管理项目素材」的闭环。

- 不改原灵感库的录入、搜索、详情编辑、全局收藏夹分享、单素材分享与数据页口径。
- 不在 `items` 写项目 ID、项目收藏或排序；项目与素材只能通过独立关联表连接。
- 不引入账号、多用户、协作编辑、对象存储、自建后端、AI 推荐或跨平台自动抓取。
- 第二期的 Markdown 导出与项目访客只读分享不在本期实现，避免与现有分享路径和令牌规则混改。
- 所有新增写操作必须通过 `app/store.js` 的 `guard()`；页面不能直接连数据库。

## 1. 已确认需求

| 主题 | 一期规则 |
|---|---|
| 项目名称／构思 | 都可为空；名称为空时保存为“未命名项目” |
| 筛选标签 | 可选多个既有标签；未选时翻阅全库；多标签命中任意一个即可出现 |
| 素材关系 | 同一素材可收藏进多个项目；同项目内不可重复收藏 |
| 翻阅 | 中央主卡＋左右各至少三层横向叠放；整组跟手、跨阈值翻页、未跨阈值回弹 |
| 收藏 | 右下爱心；已收藏为红色；再次点击直接取消，实心转空心／缩放并提示“已取消收藏” |
| 进度 | 不跨设备保存上次翻阅位置；重新进入按当前项目筛选范围开始 |
| 项目状态 | 可手动归档、恢复、删除；归档项目仍显示并标注；删除前二次确认 |
| 项目素材集 | 支持手动拖拽排序；只影响当前项目 |

完整需求与视觉细则以 `PRD.md` 为准；每次规则变化追加 `项目修改记录.md`，不要只改代码。

## 3. 数据方案（实施前回读）

### 3.1 `projects`

建议字段：`id`、`user_id`、`name`、`brief`、`filter_tags text[]`、`status`（`active`／`archived`）、`created_at`、`updated_at`。

约束：名称由页面在空值时归一为“未命名项目”；`status` 只允许 `active` 或 `archived`；`filter_tags` 默认空数组。

### 3.2 `project_items`

建议字段：`project_id`、`item_id`、`saved_at`、`sort_order`。

约束：`(project_id, item_id)` 唯一；两个外键均 `on delete cascade`。删除项目仅删关联；删除原素材自动删关联；排序只更新该项目关联的 `sort_order`。

### 3.3 迁移纪律

1. 先形成可审查 SQL，再执行线上迁移；同时更新 `data/schema.sql`。✅ 已于 2026-09-23 在线执行并同步 `data/schema.sql`。
2. 验证写入后必须按项目 ID 和素材 ID 回读；测试数据清理后再回读一次。⏳ 建表回读已通过；**写入往返回读待页面数据层完成后补做**（本次未写测试数据，无残留）。
3. 补齐新表的 GRANT、RLS 与 policy，不能只建表。✅ 已随迁移执行并回读确认。
4. 迁移或生产写入失败时，不宣称一期完成，也不以界面状态替代数据库真值。
5. **平台的 SQL 执行通道单次只接受一条语句**（多条会返回 `cannot insert multiple commands into a prepared statement`），因此迁移脚本的 `begin; … commit;` **不能作为单个事务整体执行，没有原子性**。执行时必须逐条提交，并注意 `create table` / `create index` / `create policy` 都不是幂等写法（无 `if not exists`）：中途失败需人工判断已完成到哪一步再决定如何续跑。对已有数据的表做不可逆 DDL 前，先本地演练或改成幂等写法。

## 6. 一期验收

1. 名称、构思和标签为空时可建“未命名项目”；无标签翻阅全库。
2. 多标签时，命中 `ai_tags` 或 `my_tags` 中任一所选标签的素材可出现；不命中者不出现。
3. 同一素材能进入两个项目；取消其中一个后另一个关系仍在；`items` 行无项目字段变化。
4. 已收藏素材继续出现，红心状态准确；取消后关系被移除并出现明确反馈。
5. 拖拽排序后，刷新并按项目 ID 回读，顺序仍与界面一致。
6. 归档后仍显示“已归档”；恢复为进行中；删除二次确认后只删除项目与关联。
7. 从指定项目、指定翻阅卡进入详情再返回，项目与素材上下文不丢失。
8. 1440px、768px、390px 下无横向溢出；手机端左右各三层预览卡不压迫主卡；既有首页验证无回归。
