## 1. 需求来源与目标

Elangit 目前解决的是“把日常积累的案例素材收进来，并在需要时找回”。本功能补齐设计项目启动时的下一步：用户建立一个具体项目后，在不离开灵感库、不重新整理素材的前提下，快速浏览既有案例，把合适的素材收进该项目的参考集。

### 1.1 产品目标

1. 用户能为一个设计项目建立独立容器，写下项目名称和初步构思。
2. 用户能在沉浸式单卡翻阅中逐张判断素材，而不是回到常规卡片栅格逐项打开。
3. 用户能把同一条既有素材收藏到一个或多个项目；该操作只建立关联，绝不复制、移动或改写原素材。
4. 用户能随时回到某个项目，查看其已收藏的参考素材。

### 1.2 核心原则（已确认）

- **原灵感库功能不变**：原有录入、素材浏览、搜索筛选、详情编辑、全局收藏夹分享、数据页继续按原逻辑工作。
- **项目收藏不是全局收藏**：项目内的“收藏”只表示“此素材适用于此项目”，不得改变原有分享收藏夹或素材自身字段。
- **收藏是明确动作**：左右滑动只切换素材；不会把“略过”解释成不喜欢、删除或永久排除。
- **详情判断不断流**：从翻阅页进入详情后，返回必须回到同一项目、同一张翻阅卡。
- **不扩大范围**：首版不做 AI 自动推荐、不做项目协作／账号体系、不做项目素材的跨平台自动抓取。

## 2. 用户场景与主流程

### 2.1 场景

“我正在启动一个设计项目，想到平时积累过一些可能有用的案例。我新建项目、写下构思，然后像翻书一样看库中的素材。遇到可能有用的就先进入详情确认；确认后返回卡片点收藏，最后在项目里得到一组可继续研究的参考素材。”

### 2.2 主流程（拟定）

```text
素材库首页
  → 新建项目
  → 填写项目名称 / 初步构思 / 筛选标签（均可留空）
  → 项目工作台
  → 快速翻阅（单卡）
  → 左右滑动切换素材
  → 进入详情核对
  → 返回原卡
  → 收藏到当前项目
  → 项目参考素材集
```

### 2.3 页面职责（拟定）

| 页面 | 职责 | 不应承担的职责 |
|---|---|---|
| 素材库首页 | 保持原卡片栅格、搜索与筛选；提供进入“项目工作台”及“新建项目”的入口 | 不把项目状态、项目筛选或项目收藏混进原列表卡片 |
| 项目工作台 | 展示项目名称、初步构思、已收藏数量；提供“快速翻阅”与“参考素材”入口 | 不替代素材库的搜索与编辑能力 |
| 快速翻阅页 | 居中呈现一张书籍式素材卡；横滑/左右按钮切换；卡面只保留项目收藏按钮 | 不展示编辑、删除、全局分享等原素材操作 |
| 素材详情 | 复用已有详情信息以供核对；识别来自翻阅页的返回上下文 | 不改变原有详情、编辑和普通返回路径 |
| 项目参考素材页 | 展示当前项目已收藏的素材，允许打开详情并取消项目收藏 | 不删除原素材、不改其抽屉／标签／全局收藏夹 |

## 3. 功能需求（草案）

### P1 项目建立与管理

| 编号 | 需求 | 优先级 |
|---|---|---|
| P1-1 | 用户在所有者解锁后可新建项目。 | P0 |
| P1-2 | 项目名称与初步构思均非必填；名称为空时自动显示并保存为“未命名项目”。 | P0 |
| P1-3 | 用户可重新打开已有项目并继续工作。 | P0 |
| P1-4 | 项目工作台显示该项目已收藏素材的计数。 | P0 |
| P1-5 | 项目支持手动归档、恢复与删除；归档、恢复、删除均不得删除原素材。已归档项目仍显示在项目列表中，并有“已归档”标记，可恢复为进行中；删除项目只移除该项目及其项目素材关联，且删除前必须二次确认。 | P1 |
| P1-6 | 新建／编辑项目时可选择一个或多个既有标签，作为该项目快速翻阅的默认素材范围。 | P0 |

### P2 快速翻阅

| 编号 | 需求 | 优先级 |
|---|---|---|
| P2-1 | 用户进入快速翻阅后，系统以一张居中的书籍式素材卡为焦点；左右两侧**各至少三张**相邻卡沿横向队列错位重叠、逐级缩小并弱化，形成连续翻页感，**不得上下叠放**。桌面端沿用已确认的牌堆比例；手机端两侧卡片需比桌面端更快缩小、降低显著度，确保中央主卡始终是视觉焦点。 | P0 |
| P2-2 | 用户可用触控横滑切换上一张／下一张；桌面端提供等价的左右操作。切换方向与两侧露出的卡片方向一致。**桌面端的等价操作包含触控板双指左右滑动／鼠标横向滚动**（笔记本用户不接鼠标，双指滑是他们的第一直觉）。横向滚动按**连续滚动**处理：位移与手势 **1:1 跟手**（不打折），每走满一格当场翻一张（`⌊总位移 ÷ 步长⌋` 张，不封顶），不足一格的余量在空闲时回弹；滑到队列两端即停，两个方向对称。纵向滚动不翻页，留给页面与卡片背面的长文本。 | P0 |
| P2-2a | 用户拖拽时，中央卡与左右各三层预览卡应作为**同一横向牌堆**跟随手势连续位移：所有卡片同步改变位置、缩放、透明度与层级；不得用“当前卡消失、下一张淡入”的替换式转场冒充翻页。 | P0 |
| P2-2b | 用户松手后，超过经原型测试确认的距离或速度阈值才完成翻页；未达到阈值则整组卡片回弹到原位。两个方向的规则、时长与回弹感必须对称。**此条只约束拖拽（指针）路径**：拖拽仍用分段阻尼与阈值判据；滚动路径按 P2-2 的连续滚动规则处理，两者不共用阈值（v0.5 曾要求共用，实测证明会同时毁掉两边的操作手感）。 | P0 |
| P2-2c | 当前主卡仅保留右下角收藏爱心作为显式操作；爱心点击目标须适配手机触控，同时为左下角的分类与标题留出不重叠的阅读空间。 | P0 |
| P2-2d | **点击旁侧卡＝把牌堆滚到那一张**（该卡成为中央主卡），**不翻转它**。旁侧卡在视觉上只是“前后还有素材”的提示，没有正反面可言；点它的意图是“我要看这一张”。因此侧卡是**可点**的（不能被透明面吃掉点击），但其中的爱心／详情等显式按钮只对中央卡生效。 | P0 |
| P2-3 | 左右切换不写入“喜欢／不喜欢／已排除”等判断，也不改动素材。 | P0 |
| P2-4 | 卡面除“收藏到当前项目”外不放置素材编辑、删除、分享等操作。**点卡体翻转到背面阅读该素材的设计说明总结**（`ai_digest` 的理念／做法／效果三段）；**进入详情走背面右下角的「详情」入口**（与正面爱心同一视觉锚点），点卡体本身不再跳转。素材没有合格总结时，背面如实说明“没有”，不得拿其他字段凑成一段断言其可信的文字。 | P0 |
| P2-5 | 若素材已经收藏到当前项目，按钮显示明确的已收藏状态，避免重复收藏。 | P0 |
| P2-6 | 从翻阅页进入详情再返回时，系统恢复至同一个项目与同一张卡。 | P0 |
| P2-7 | 空库、项目内尚未收藏、库中只剩一条可浏览素材、无封面／纯文本素材都必须有准确状态。 | P0 |
| P2-8 | 已收藏素材继续出现在翻阅队列；当前项目已收藏时，右下爱心保持红色已收藏样式。再次点击直接取消项目收藏，无需确认；爱心须以明显的红色实心转空心／缩放反馈，并配合“已取消收藏”提示，区别于收藏成功。 | P0 |
| P2-9 | 跨设备不保存翻阅进度；重新打开项目时按该项目当前默认筛选范围重新开始浏览。 | P0 |
| P2-10 | 未选择项目标签时，快速翻阅默认读取全库素材；选择多个标签时，素材命中任意一个所选标签即可进入队列。 | P0 |
| P2-11 | 阅读状态与翻阅手势不可同时存在：拖拽或横向滚动一开始（位移越过点击／拖拽的分界），卡片先**瞬时复位回正面**，再完成翻页；翻面只在静止时成立。翻面**只发生在中央卡上**——点旁侧卡是「滚到那一张」（P2-2d），不翻面；任何位于侧位的卡片都不得处于翻面态（否则它会跟着滚到中央并停成背面）。同一张牌被复用到另一条素材时必须回到正面；同一条素材的重画（例如缩略图迟到）保留用户已经翻到的那一面。桌面端与手机端行为一致，不留差异。 | P0 |

### P3 项目参考素材集

| 编号 | 需求 | 优先级 |
|---|---|---|
| P3-1 | 已收藏素材在项目内聚合为独立参考素材集。 | P0 |
| P3-2 | 同一素材可被收藏到多个项目；每个项目的收藏关系独立。 | P0（拟定） |
| P3-3 | 用户取消项目收藏时，仅移除该项目与素材的关系，原素材和其他项目关系保持不变。 | P0 |
| P3-4 | 原素材被删除后，不得在项目中留下可点击的失效引用。 | P0 |
| P3-5 | 项目参考素材集支持用户手动拖拽排序；排序结果仅影响当前项目，不改动原素材与其他项目。 | P1 |
| P3-6 | 项目参考素材集支持导出为 Markdown（`.md`）文件。 | P1 |
| P3-7 | 项目支持生成访客只读分享链接；分享页展示项目名称、构思、筛选标签与该项目全部已收藏素材。 | P1 |

## 4. 信息与数据关系（方案）

项目必须与既有 `items` 表解耦；不得把项目 ID、收藏状态或项目备注塞进 `items`，否则一条素材进入多个项目时会互相覆盖。

```text
projects（一个设计项目）
  1 ──< project_items（项目与素材的关联） >── 1 items（既有素材）
```

### 4.1 拟新增表：`projects`

| 字段 | 含义 | 规则 |
|---|---|---|
| `id` | 项目 ID | 自增主键 |
| `user_id` | 预留用户字段 | 继续沿用固定值 `local-owner`，不引入账号体系 |
| `name` | 项目名称 | 可为空；为空时持久化为“未命名项目” |
| `brief` | 初步构思 | 可为空 |
| `filter_tags` | 默认筛选标签 | 既有标签名称的数组；可为空，匹配规则见第 8 章 |
| `status` | 工作状态 | 至少区分进行中与已归档；恢复细则待确认 |
| `created_at` / `updated_at` | 建立／最后更新 | 时间戳 |

### 4.2 拟新增表：`project_items`

| 字段 | 含义 | 规则 |
|---|---|---|
| `project_id` | 所属项目 | 外键，项目删除时关联一并删除 |
| `item_id` | 既有素材 | 外键，原素材删除时关联一并删除 |
| `saved_at` | 收藏到该项目的时间 | 用于展示与后续排序 |
| `sort_order` | 项目内排序 | 用户手动拖拽后写入；仅影响当前项目 |

唯一约束应为 `(project_id, item_id)`：同一素材在同一项目只保留一条关联，但可在不同项目分别出现。

### 4.3 翻阅进度（已确认）

跨设备不保存“上次翻到哪一张”。因此不为项目增加翻阅位置字段，也不产生对应写入；每次打开项目均按当前默认筛选范围重新生成翻阅队列。

## 5. 技术融入边界（方案）

### 5.1 文件边界

本功能的产品文档与变更记录固定放在：

```text
features/项目灵感筛选/
  PRD.md
  项目修改记录.md
```

获准开发后，功能代码拟隔离在 `app/projects/`，由原页面以明确入口跳转；共享的素材读取、图片渲染与所有者门禁继续复用现有模块。现有首页、录入、详情、分享与数据页不被重写。

拟定结构如下；名称只用于方案评审，开始开发前仍应按获确认的页面命名落地：

```text
app/
  projects/
    index.html        # 项目列表与新建项目入口
    workspace.html    # 单个项目的工作台与参考素材入口
    deck.html         # 单卡快速翻阅
    projects.js       # 本功能的页面状态与交互
    projects.css      # 本功能限定样式
  store.js            # 仅新增 projects / project_items 的统一读写方法
  item.html           # 仅识别来自 deck 的返回上下文
```

这里的 `store.js` 例外是必要边界，而不是把功能代码散回主应用：它是现有全部云端读写的唯一数据访问层，新表的任何新增、更新、删除也必须在此复用 `guard()`，否则会绕开所有者门禁。

### 5.2 需要复用的既有能力

- `store.js` 的瘦身列表查询：翻阅页只读取卡面所需字段，不读取 `item_images.data_base64`。
- `item.html`：详情只增加“从项目翻阅页返回”的上下文，不复制第二份素材详情。
- `auth.js` / `store.js` 的 `guard()`：新建项目、收藏／取消收藏和项目编辑均必须走同一所有者门禁。
- `cards.js`：项目参考素材集如复用卡片，应复用公开渲染规则，不能另写一份素材解释。
- `style.css` 的产品变量与构件：项目页沿用现有 `--bg`／`--surface`／`--line`／`--ink`、58px 顶栏、10px 圆角、细边框与系统中文字体；不能为新功能另造一套视觉语言。

### 5.3 明确不触碰的内容

- 不改变现有素材的字段含义、AI 处理、抽屉、标签与检索口径。
- 不改变全局收藏夹分享和单条分享的授权／链接规则。
- 不为项目功能引入账号、多用户协作、对象存储、自建后端或外部抓取。
- 不把快速翻阅的“略过”写成用户偏好数据，避免制造无法解释的埋点和误判。

### 5.4 已核实的接入事实

| 事实 | 对本功能的影响 |
|---|---|
| `tools/build-deploy.py` 会递归复制 `app/` 下的普通子目录，并仅排除 `_verify_` 前缀／`_verify_shots`。 | `app/projects/` 能随现有发布流水线发布，无需改发布架构；专属验证页须继续用 `_verify_` 前缀。 |
| `app/_serve.py` 只对 `/s/`、`/i/` 分享地址做特殊重写，其他静态子路径照常提供。 | `projects/` 页面不需要新增服务端路由；子目录页面必须使用 `../style.css` 等正确相对路径。 |
| `store.js` 中的 `guard()` 是所有现有写操作的共同门禁。 | 建项目、收藏／取消收藏、项目编辑／删除必须都通过新增的 store 方法，页面不得直连数据库。 |
| 首页顶栏在 390px 宽有已验证的无换行约束。 | 若增加“项目”或“新建项目”入口，必须把该入口纳入现有五页面 × 三档宽度的版式回归，不可只在桌面验证。 |
| `loadIndex()` 刻意不取缩略图，`cardsByIds()` 才按需取卡面。 | 翻阅队列先复用轻量索引，再按当前／相邻卡按需取缩略图；不得读取 `item_images.data_base64` 作为翻阅列表数据。 |
| 原浏览页侧栏为 224px，且手机端会收束为横滑筛选。 | 项目翻阅页的左右功能栏应比浏览页侧栏更窄；手机端不保留双侧栏，改为卡片上方的紧凑项目／已收藏入口，把横向空间让给主卡与两侧预览卡。 |

### 5.5 数据迁移与埋点原则

1. 在用户确认数据模型后，先提交 `projects`／`project_items` 的线上迁移语句和 `data/schema.sql` 同步更新方案；迁移前不假设线上库已存在这些表。
2. 对迁移写入的测试，必须以项目 ID 和素材 ID 回读验证，再清理测试关联并再次回读。
3. 首版不新增浏览或收藏埋点：项目数、某项目已收藏数、素材被引用项目数都可由 `projects` 与 `project_items` 当前状态派生。除非后续明确要衡量“翻阅是否帮助决策”的过程问题，否则不另存会漂移事件。

## 6. 分期实施顺序（已确认）

### 第一期｜项目建立、筛选与快速翻阅

1. **数据迁移验证**：新增 `projects`／`project_items`、约束和索引；做多项目收藏、取消关联与删除源素材的回读验证。
2. **数据访问层**：为项目、关联关系和按需卡面读取补齐 `store.js` 方法，所有写入经 `guard()`。
3. **项目工作台与入口**：实现项目列表、新建项目／编辑、标签选择、归档／恢复／删除和项目参考素材集；验证它们不改变原素材字段。
4. **快速翻阅与详情返回**：在独立页面实现牌堆队列、触控／桌面等价操作、显式收藏／取消收藏、手动排序和返回上下文。
5. **一期回归与验收**：运行既有首页版式验证，补本功能验证台，进行数据库回读与真实手机手测；通过后才讨论一期发布授权。

### 第二期｜项目交付与只读分享

1. 在一期稳定的数据模型上实现 Markdown 导出，导出内容以当前项目的名称、构思、筛选标签和手动排序后的素材集为准。
2. 为项目生成独立访客只读分享链接；复用现有路径式分享和只读渲染的安全边界，不影响全局收藏夹／单素材分享。
3. 对导出与分享做桌面／手机、访客态、失效／撤销链接和既有分享链接回归；通过后单独申请二期发布授权。

## 7. 验收与验证计划（实施前确认）

| 验收项 | 证明方式 |
|---|---|
| 原素材库功能未回归 | 对首页录入、检索、详情、分享、数据页执行既有验证台与关键手测；页面错误为 0 |
